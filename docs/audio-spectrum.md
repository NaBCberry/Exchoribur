# 音频频谱

导入参考视频或打开含参考视频的工程后,在后台解析默认音轨。频谱区域中央显示
解析进度,期间可以继续编辑与播放。切换媒体、新建工程和退出会取消旧任务;
旧进度与旧结果不会覆盖当前工程。失败时可重试,没有音轨时显示提示。

横轴与主时间轴共用视口、留白、缩放与平移,侧栏开合后仍保持相同轨道宽度。
点击或拖动频谱可定位播放头,定位限制在视频范围内,范围外沿用灰色蒙版。

## 解码与时间对齐

预览继续使用 LibVLC;频谱直接调用 FFmpeg 8.1 的 libavformat、libavcodec 和
libswresample,不启动命令行进程,不解码视频,不读取系统或播放器时钟。

- 用容器 `start_time` 建立共同原点,解码帧的 `best_effort_timestamp`/`pts`
  按音轨 `time_base` 转换后映射到时间轴。不会将第一帧音频直接归零,因此音轨
  相对视频的真实延迟被保留。没有帧时间戳时才按音轨起点和样本数连续推进。
- 编码器预热与 MP4 编辑列表交由解复用器/解码器处理;时间零点前的输出仅裁去
  负时间样本,不添加经验偏移。先前 smem 时间基准的问题见
  [时间基准调查](audio-spectrum-clock-research.md)。
- 持续重采样为单声道 48000 Hz,保留重采样器的小数余量,以实际输出样本数推进。
  结束时排空解码与重采样尾帧,避免逐包取整造成长音轨漂移。
- 真正的帧时间断点先排空旧片段再重置重采样器,保留断点处的空白。
  音轨中途切换采样格式暂不支持,会显示解析失败,不会错误解释原生缓冲。

## 频带与显示

4096 点 Hann 窗、2048 点步进进行短时傅里叶变换,每列约 42.67 ms。
纵轴显示 20 Hz 至24 kHz 的 96 个对数频带,保存 -90 至 0 dB 的强度。
低频显示频带可能比 FFT 频率间距更窄,因此按中心频率插值功率;较宽频带取
覆盖频点的峰值。相邻细频带并不代表获得了比 FFT 本身更高的频率分辨率。

连续窗口中心映射到均匀时间列时,跨列取整造成的空列由相邻数据插值补齐;
真实音轨断点不会被补画。显示色表压低弱背景并拉开强弱差异,提高对比度;
显示调整不改变保存的分析数据。纵轴按对数位置显示 Hz/kHz 刻度与细网格线;面板较矮时自动省略拥挤的中间标注。

48 kHz 解析采样率覆盖最高 24 kHz。低采样率源文件重采样不会增加原本不存在的高频内容;其高频区可能保持暗色。新的算法版本使用独立缓存键,旧的 11 kHz 结果不会被误读。

## 任务、缓存与性能

文件及原生媒体访问位于 Infrastructure,界面只通过 `IAudioSpectrumAnalyzer`
调用服务,频谱运算和只读数据位于 Core。耗时工作在后台进行,进度约每 100 ms
更新一次,最多同时解码一个媒体。退出时异步等待任务释放原生资源。

不保留完整 PCM;复用解码与重采样缓冲。结果生成按时间最大值合并的显示层级,
只绘制可见范围,播放头移动不重建频谱位图。数据保护上限为 100 万列
（约 11.9 小时）,防止损坏时间戳导致无界分配。

缓存位于用户本地应用数据目录 `Exchoribur/SpectrumCache`,按路径、文件大小、
修改时间与算法版本区分,与旧版实验解析缓存隔离。只原子写入完整结果,损坏缓存
重新解析,总量约限 512 MB。缓存写入失败仍可显示解析结果。

## 原生依赖

Windows x64 开发前运行 `pwsh scripts/prepare-ffmpeg.ps1`,然后正常构建。
脚本下载固定版本的 LGPL shared 构建并校验 SHA256,只复制四个动态库。
构建与发布自动将其复制到输出目录 `ffmpeg/`,CI 和 Windows 打包流程也调用
同一脚本。首次下载需要网络,已下载且摘要正确的压缩包可重复使用。

macOS/Linux 需要兼容 FFmpeg 8.1 的动态库。macOS 默认检查 Homebrew 的
`/opt/homebrew/opt/ffmpeg/lib` 或 `/usr/local/opt/ffmpeg/lib`,Linux 使用系统
动态库搜索路径。均可用 `EXCHORIBUR_FFMPEG_DIRECTORY` 指定目录。不同 ABI
主版本不会混用。库不可用时仍可编辑与预览视频,频谱区域显示失败与重试。
许可、来源与构建配方见 [第三方声明](../THIRD-PARTY-NOTICES.md)。

## 验证

自动测试覆盖已知频率、宽带噪声所有频带、连续时间列、静音、偏移、真实断点、
短音频、分包、多级聚合,以及进度、取消、过期结果、失败重试和侧栏布局。
Windows 原生集成测试验证 WAV 时长与静音、缓存损坏重建、延迟 AAC 音轨、
非零容器原点、重复解析一致性及两分钟 44.1/48 kHz 重采样尾部。
测试用 MP4 是自行生成的黑色视频和正弦音,生成方法见测试素材说明。

其他平台的原生解码与实际屏幕渲染仍需在对应系统验收。
